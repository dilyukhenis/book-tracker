# Дневник книг

CRUD-приложение для учёта прочитанных книг на чистом PHP 8.1 — без фреймворка
и без Composer: роутинг, валидация, авторизация и слой данных написаны вручную,
чтобы показать понимание базовых механизмов.

## Запуск

    docker compose up --build

Приложение: http://localhost:8000 — начните с регистрации.

База — SQLite, файл `data/app.sqlite` создаётся автоматически при первом запросе
(таблицы `users` и `books`). Файл не попадает в git. Сброс базы — удалить файл
и перезапустить контейнер.

## Структура

    public/index.php        фронт-контроллер: сессия, автозагрузка, маршруты
    public/router.php       роутер встроенного сервера PHP
    src/Database.php        PDO-подключение и создание схемы
    src/Router.php          маршрутизация по регулярным выражениям
    src/View.php            рендер шаблонов с layout
    src/Auth.php            вход, выход, текущий пользователь
    src/Csrf.php            генерация и проверка токенов
    src/Flash.php           одноразовые сообщения
    src/Validator.php       декларативная валидация
    src/BookRepository.php  слой данных, пагинация и поиск
    src/helpers.php         e(), redirect()
    src/Controller/         обработчики запросов
    views/                  шаблоны

## Что реализовано

- Регистрация и вход: `password_hash` / `password_verify`, `session_regenerate_id`
  при входе, защита от фиксации сессии.
- CSRF-токен на каждой POST-форме, сравнение через `hash_equals`.
- Экранирование вывода через `e()` (`htmlspecialchars` с `ENT_QUOTES`).
- Все запросы — только подготовленные выражения PDO, SQL-инъекции исключены.
- Проверка владельца: `find($id, $userId)` — чужую книгу по прямому URL не открыть.
- Пагинация с сохранением поискового запроса, `LIMIT/OFFSET` через привязку
  параметров, экранирование `%` и `_` в LIKE.
- Валидация на сервере: обязательные поля, длины, целые числа, допустимые
  значения статуса; ошибки показываются у полей, введённые значения сохраняются.

## Ограничения и следующий шаг

- HTML-формы не умеют PUT/PATCH/DELETE — всё через POST (в реальном проекте
  нужен method spoofing или PATCH-эндпоинт).
- Нет rate limiting на вход — кандидат на следующую итерацию.
- Пагинация выводит все номера страниц — при большом объёме нужен диапазон.
- Следующий шаг — переписать на Laravel: миграции, Eloquent, Form Request,
  middleware и Policy вместо ручных проверок.
